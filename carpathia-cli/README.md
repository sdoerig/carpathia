# Description

Carpathia is a CLI tool that generates database access code from your schema. You write the Tera templates—it produces the code. Currently supports Postgres (MySQL & SQLite planned). Functional but in beta: use it, test it, and help shape its future! 🚀
# carpathia-cli — Rust Database Schema Code Generator

> Generate Rust database access code from PostgreSQL schemas using customizable Tera templates.

`carpathia-cli` is a command-line tool that connects to a PostgreSQL database, extracts its schema (tables, views, columns, constraints), and generates Rust code based on user-defined Tera templates. It intelligently skips re-generation if nothing has changed — thanks to a built-in hash-based cache.

Perfect for teams building type-safe, maintainable database layers in Rust without writing boilerplate by hand.

---

## ✅ Features

- ✅ Extracts **tables, views, materialized views**, and column metadata from PostgreSQL
- ✅ Generates code using **Tera templates** (`.tera` files)
- ✅ **Caching**: Only regenerates files when schema or templates change
- ✅ **Type mapping**: Map PostgreSQL types to custom Rust types via `carpathia_type_mapping.json`
- ✅ Supports **dry-run**, **debug output**, and **schema inspection**
- ✅ No external dependencies beyond Rust and PostgreSQL

## 🚀 Quick Start

### 1. Install
Build it from source

```bash
git clone git@github.com:sdoerig/carpathia.git
cd carpathia
cargo build --release
```

### 2. Prepare a PostgreSQL Database
Ensure you have a PostgreSQL server running and a database with a schema (e.g., Pagila).

### 3. Create a Template Directory
Create a folder for the tera files 

```bash
mkdir -p templates/rust_lib
Example template: templates/rust_lib/tables.user.rs.tera
```

```rust
// Generated by carpathia-cli
#[derive(Debug, Clone)]
pub struct {{ table_name }} {
{{- for attr in table.attributes }}
    pub {{ attr.column_name }}: {{ attr.u_type }},
{{- end }}
}
```

### 4. Create a Type Mapping File
Create carpathia_type_mapping.json - use the `--print-db-types` flag.

```bash
carpathia execute --db-host 127.0.2.15 --db-port 5432 --db-username doerig --db-password doerig --db-type postgres --db-name pagila   --print-db-types > my_type_map.json
```
The file my_type_map.json is now your typemapping used to generate your code. Its only purpose is translating database types to the types in your code. The file 
contains the section `db_to_code_names_mapping`. This mapping will be applied to any table or attribute name and you will find them in the `u_`.
```json
{
  "version": "0.1.0",
  "type_mapping": {
    "boolean": {
      "u_import": "",
      "u_type": ""
    },
    "bytea": {
      "u_import": "",
      "u_type": ""
    },
    "character(20)": {
      "u_import": "",
      "u_type": ""
    },
    "date": {
      "u_import": "",
      "u_type": ""
    }
  },
  "db_to_code_names_mapping": {}
}
```

### 5. Print schema

As for template writing, the structure of carpathia is important. You can print it with:

```bash
carpathia execute --db-host 127.0.2.15 --db-port 5432 --db-username doerig --db-password doerig --db-type postgres --db-name pagila   --template-directory /tmp/templates/  --output-directory /tmp/out/ --carpathia-type-mapping-file fixtures/carpathia_type_mapping.json  --print-schema
```

The printed structure can be regarded as a contract. Any field prefixed with `u_` is one you can define with the type mapping. It's up to you using them or not.

```json
      ],
      "table_properties": [
        {
          "PrimaryKey": {
            "columns": [
              {
                "constraint_name": "actor_pkey",
                "key_type": "SingleColumn",
                "column": "actor_id",
                "u_column": "actor_id"
              }
            ]
          }
        }
      ],
      "attributes": [
        {
          "column_name": "actor_id",
          "u_column_name": "actor_id",
          "data_type": "integer",
          "u_type": "i32",
          "is_nullable": "No",
          "column_default": "nextval('actor_actor_id_seq'::regclass)",

          "character_maximum_length": null,

          "numeric_scale": 0,

            "NotNull": {
              "constraint_name": "actor_id_not_null",
              "constraint_value": "NOT NULL"
            }

```
### 5. Init templates
`carpathia` comes with one template set included. To extract it just do
```bash
carpathia  --init-template rust-lib --template-directory ./templates/
```


### 5. Run the Generator
```bash
carpathia execute --db-host 127.0.2.15 --db-port 5432 --db-username doerig --db-password doerig --db-type postgres --db-name pagila   --template-directory /tmp/templates/  --output-directory /tmp/out/ --carpathia-type-mapping-file fixtures/carpathia_type_mapping.json``
```

📁 Template Naming Convention
Templates are categorized by prefix:

Prefix  Purpose Example
tables.*.tera Generate one file per table tables.user.rs.tera → user.rs
views.*.tera  Generate one file per view  views.user_summary.rs.tera → user_summary.rs
summary.*.tera  Generate one summary file with full schema  summary.mod.rs.tera → mod.rs
The suffix (e.g., .rs, .html) is preserved. Use {{ table_name }} and {{ table.attributes }} in templates.
